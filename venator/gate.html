The model reads the message. The code makes the decision.

An LLM is genuinely good at reading messy human text — and genuinely unsafe as an authority. It hallucinates, it can be injected, it fails non-deterministically. Money needs an answer defensible to a regulator, not a plausible paragraph. So the two are split: the model produces an opinion; deterministic Python owns every decision.

The modelReads the message. Returns a risk score, a confidence, a plain reason. That is all it can do.
The codeReads the facts, applies the rules, decides. One guarded writer owns every state change.

How it works

One triage chain, six stages. Five gather facts or an opinion. One decides. One moves money — and it is the only function in the system that can.

FactsRead the transaction. get_transaction_context() — who, how much, to whom.
FactsCheck known scam links. check_scam_link() — free, and runs first.
OpinionThe model reads the message. Risk score, confidence, a plain-English reason. Never a decision.
FactsVerify the recipient. verify_campus_recipient() — verified vendor, or a two-day-old account?
DecisionThe guard decides. A pure function, first rule wins, every threshold read from policy.
MoneyOne writer changes state. update_payment_state() — the only legal path to a wallet.

What the design guarantees

Each of these is enforced by structure, not by care.

No permanent freeze

There is no BLOCK state. The schema cannot express one. Worst reachable state is “waiting on a person”.

One writer

update_payment_state() is the only function that mutates a wallet, and it rejects illegal transitions outright.

Degrades, never fails

Model down, model unsure, directory hanging — all modelled states with defined behaviour. The wallet stays open.

No unbounded loop

Nothing polls. A payment awaiting a human is never re-processed. At most one model call per payment.
